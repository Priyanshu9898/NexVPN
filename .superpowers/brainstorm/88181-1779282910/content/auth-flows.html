Section 2 — Backend Auth Flows

Three flows: Google OAuth, Forgot Password, and RBAC middleware

🔵 Google OAuth Flow

OAuth Dance
Browser
Fastify Backend
Google
GET /auth/google→redirect to Google→consent screen
user approves→GET /auth/google/callback?code=…
→exchange code for profile
upsert user in DB (create or find by googleId)
issue JWT + refresh token
→redirect to /auth/callback?token=… on frontend
store token, redirect to /dashboard

🔴 Forgot Password Flow

Reset Dance
POST /auth/forgot-password { email }
→ generate 32-byte random token
→ store bcrypt(token) + expiresAt (1hr) in PasswordResetToken table
→ send email via Nodemailer: nexvpn.com/reset-password?token=RAW_TOKEN
→ always return 200 (don't leak whether email exists)
POST /auth/reset-password { token, newPassword }
→ find PasswordResetToken where used=false AND expiresAt > now
→ bcrypt.compare(token, tokenHash)
→ update user passwordHash, mark token used=true
→ return new JWT pair (auto-login after reset)

🟢 RBAC Middleware

Role Guard
JWT payload now includes role:
{ sub, email, plan, role: "admin" | "user" }
Two middleware layers:
authenticate → verifies JWT, attaches nexvpnUser (existing)
requireAdmin → checks nexvpnUser.role === "admin", returns 403 if not
Admin routes sit behind both:
preHandler: [authenticate, requireAdmin]
New route prefix:
/api/v1/admin/users
/api/v1/admin/nodes
/api/v1/admin/audit-logs
/api/v1/admin/subscriptions
